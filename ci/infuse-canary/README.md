# Frozen Infuse canary hosted build

This bootstrap is a separate payload for `codex/v2026.10.2-infuse-canary-build` in the existing public fork `aolea/openclaw`. It must not be added to the candidate source commit. Source is fixed at `7494b64ee37d2cce1e9fd1873180eb35ea75f9e9`, stable base `b8952d477f0c932d8ddc6da5c89cab5a169b6ff1`, timestamp `2026-10-12T23:12:45.000Z`. The complete source and lock hashes are in `binding.json`. There are no inputs that can select a different source, time, repository or runner.

Publication of the source and this bootstrap requires the parent's explicit user approval. The exact bootstrap branch push automatically starts its fixed-candidate job, and that start is part of the required publication approval. This preparation does not push, start CI, create a release/tag, publish npm packages or deploy anything. The workflow has only `contents: read`; no token, OIDC, attestations, cache, secret, Docker socket or user directory reaches candidate execution.

GitHub documents standard public `ubuntu-24.04` as a fresh 4-CPU/16-GB hosted VM with free standard Actions compute: https://docs.github.com/en/actions/reference/runners/github-hosted-runners. This workflow uses no larger/paid/self-hosted runner. Temporary artifacts are capped at 400 MiB and retained for one day; it creates no GitHub Release assets.

The trusted host runner builds only its own public-tool Docker context, before the candidate is available to the image. Official Node 24.21.0 AMD64 is pinned by manifest digest, verified anonymously against Docker's official registry. Official native pnpm 12.5.1 is downloaded at its exact URL and SHA512-checked. Actions checkout/upload pins come from the exact stable source workflow `.github/workflows/authorized-beta-focused-validation.yml`, not mutable action version tags.

Candidate source and Git metadata are supplied read-only to a fresh UID501 container; a UID501-owned execution copy preserves tracked bytes/modes/symlinks without preserving host ownership. Only the task work/evidence directory is writable from the host. The root filesystem and trusted harness are read-only, capabilities are dropped, no-new-privileges and Docker init are enabled, and memory/CPU are bounded at 13 GiB/4 CPUs with no swap. An empty explicit environment replaces image and Actions variables. Trusted preflight checks the actual UID, capability, privilege, memory/CPU, immutable mounts and child environment before loading candidate code.

Resource tuning keeps Go at `GOGC=30`, `GOMEMLIMIT=3GiB`, `GOMAXPROCS=4`, and Node/tsdown at an explicit 8192 MB heap. These supported environment controls leave native/compiler-owner headroom inside the 13 GiB bound while preserving the canonical guards and full check/build scope.

The candidate has a dedicated IPv4 bridge with no published ports or IPv6. Narrow firewall rules deny this bridge's traffic to the host, private/link-local ranges and cloud metadata; outbound public HTTP(S)/DNS supports canonical installs, baseline API worktrees and package metadata reads. A real trusted host sentinel has a positive control before firewall installation, and the container must fail to connect afterward. Only this invocation's named container/network and firewall chain/rules are cleaned up.

Execution is sequential: canonical frozen install with the repository's approved lifecycle policy; `pnpm check --base <stable> --include-test-types --include-architecture`; SDK export-map/subpath guards; canonical SDK API diff with exact base/head and evidence (no fabricated acknowledgement); full canonical core package with Mattermost, Codex, ACPX and diagnostics-otel; compiled SDK export checks; four canonical `plugin-npm-publish.sh --pack` plugin packages with their own runtime builds and npm lock guards. No raw npm packing, skipped DTS, check narrowing, source guard edits or consumer extras are used. Failed checks are recorded and make the final job fail even when subsequent independent artifacts succeed.

`GIT_COMMIT` and the fixed build timestamp are identical through every contributing build. Trusted source hashes and Git cleanliness are checked before/after installation and execution. The host hashes captured tracked paths after execution without invoking Git on the mutable execution tree. Artifact upload reads only a new sanitized directory of regular files after container completion, rejects symlinks/hardlinks and verifies core package/build identity and four plugin identities. Candidate stdout cannot issue GitHub workflow commands while it is streamed.

The collector rejects a symlink replacing the evidence root or its task parents, as well as descendant links. Source-integrity, artifact or package-identity refusals preserve a trusted failure summary and a bounded tail of the host-captured Docker log in an independently created upload directory; these refusals always fail the job.

The workflow triggers only on a push to the exact bootstrap branch, with additional exact repository/public/branch job guards. The parent publishes approved candidate and bootstrap commits, observes the resulting run's exact bootstrap/source identities, reviews SDK API evidence, downloads temporary artifacts, and performs the remaining installed/runtime qualification. No default-branch edit or workflow registration is needed. This bootstrap is source preparation only; its runtime boundary and gates have not yet run on a hosted runner.
